Privacy and data

This page says what HaanJi's software keeps, for how long, and how a customer can see or erase their data. The shop that runs HaanJi may also have its own privacy policy.

What is kept

  • Calls and WhatsApp messages: what the caller said, what the agent replied, and the caller's number.
  • Bookings: the service, day, time, with whom, and the customer's name and number.
  • Receipts: a signed record of every booking. The name and number in it are encrypted with a separate key for each customer.

In the browser demo, the browser's own speech recognition turns your voice into text (in Chrome this is a Google service). Only the text reaches HaanJi's server.

For how long

Calls, WhatsApp messages and missed calls are deleted on their own after 180 days. Bookings and receipts are the shop's records, so they stay.

Saying so at the start of a call

Every call can open with a line saying it is being recorded. The shop writes that line itself.

The customer's rights

  • To see: when a customer asks, the shop can see everything kept under their number: bookings, calls and receipts.
  • To erase: when a customer asks, their record is erased. The key to their receipts is destroyed, so the name and number in them can never be read again; the receipt chain still verifies.
  • To check their booking: with the confirmation code, a customer can verify their receipt in the browser themselves.

A customer can also do this themselves: on the My data page, enter the number, type the code sent on WhatsApp, and download a copy or ask for erasure. Erasure happens once the shop says yes.

On the public demo

Sign-in is off on this demo, so anyone can open the console. It shows only the last four digits of numbers, and the calendar's secret link and any number's full record stay locked. Keep this in mind before typing a real number into the demo.

Where the data lives

On the server that runs HaanJi. The code is open on GitHub, so anyone can see where in the code each thing above happens.

The days and the consent line above come from this server's real settings (/api/privacy/policy), so on every deployment this page says what is set there.
